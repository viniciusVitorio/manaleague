# Lab runtime integration contract

Owned artifacts use `infra/eks-lab/kubernetes/base/kustomization.yaml` (not the Kubernetes directory itself). Namespace: `manaleague-eks-lab`. Deployment/Service: `manaleague`; Reverb Deployment/Service: `reverb`. Cloud PostgreSQL is private Amazon RDS, not a Kubernetes workload: no PostgreSQL Service, StatefulSet or PVC is shipped. Images: `lab-app:dev`, `lab-web:dev`; build from repository-root allowlisted context using `infra/eks-lab/docker/Dockerfile --target app|web`.

Renderer must replace the **exact** tokens `__APP_URL__`, `__AVATAR_BUCKET__`, `__DB_HOST__`, `__AWS_REGION__`, `__VPC_CIDR__`, `__ALLOWED_CIDRS__`, `__SUBNET_IDS__`, `__APP_ROLE_ARN__`, `__ALB_SECURITY_GROUP_ID__`, `__RELEASE__`. `__DB_HOST__` must be the lab instance's actual RDS endpoint, not a CNAME or IP. All scalar token values are quoted. `__RELEASE__` is a lowercase DNS-safe release ID (commit SHA works). Replace `lab-app:dev` / `lab-web:dev` via Kustomize image transforms for the base and explicit replacement for Job templates. Render before validating CIDRs or applying. Fail if any token remains.

Bootstrap-only (outside base / CI deploy): `kubernetes/bootstrap/resources.yaml` creates Namespace, IRSA ServiceAccount `lab-app`, encrypted gp3 StorageClass `manaleague-eks-lab-gp3`. The StorageClass and EBS CSI addon are preserved for optional EBS-backed workloads; neither stores nor manages RDS data. `bootstrap/rbac.yaml` binds namespaced deployment access to group `manaleague-eks-lab-deploy`. It does not grant Secret/RBAC/namespace/StorageClass writes. Bootstrap externally creates Secret `manaleague-secrets` with distinct random `APP_KEY` and `DB_PASSWORD` matching the private lab RDS application user. The pipeline seed additionally requires reserved Secret `manaleague-demo` key `DEMO_PASSWORD` (20+ random characters). No Secret resources or credentials are shipped in base.

Separate explicit Jobs `kubernetes/jobs/migrate.yaml` and `jobs/seed.yaml` are never in base. Migration Job name `migrate-__RELEASE__`, seed `seed-__RELEASE__`. Same app image and IRSA account. Await private RDS availability before migrations; migrations and readiness execute remotely from app containers using the same guarded TLS connection. No StatefulSet readiness wait exists. Deploy app/reverb after successful migrations. Seeding uses an advisory lock + transaction + persistent marker; it refuses any nonempty unmarked DB, creates only synthetic `.test` users, replaces every fixed upstream demo password before commit, and is a no-op on retry. Never run upstream DemoSeeder directly.

Kubernetes PHP workloads use **args**, never **command**, to preserve the Docker safety ENTRYPOINT. Daily CronJobs run ranked scheduling each minute and isolated card-ban/card-legality/challenge maintenance at staggered UTC times.

Entrypoint and standalone seeder call shared `runtime/database-guard.php` before any database access. It requires exact `APP_ENV=eks-lab`, `DB_CONNECTION=pgsql`, empty/unset `DB_URL`, `DB_DATABASE=manaleague_eks_lab`, nonempty `APP_KEY`, and an explicit recognized `LAB_DATABASE_MODE`. Cloud ConfigMap requires `rds`: `DB_HOST` must match `manaleague-eks-lab.<alphanumeric-id>.<literal-AWS_DEFAULT_REGION>.rds.amazonaws.com`, `DB_PORT=5432`, `DB_USERNAME=manaleague_lab`, `DB_SSLMODE=verify-full`, and `PGSSLROOTCERT=/var/www/html/infra/eks-lab/runtime/certs/global-bundle.pem` must be readable. Unknown/missing modes, unrelated endpoints, region mismatch, IPs, host lists and TLS downgrade/CA override are refused. Only explicit `local` mode permits `DB_HOST=postgres` with `DB_SSLMODE=disable`; Kubernetes never supplies those settings. The seeder also validates effective Laravel config after bootstrap to reject stale incompatible cached settings.

The public official RDS global CA bundle is vendored with exact HTTPS source and SHA-256 in `runtime/certs/source.json` and `global-bundle.pem.sha256`. Docker's runtime COPY includes it, verifies its checksum and makes it world-readable (0644) for UID82. No production `config/database.php` changes: Laravel passes `DB_SSLMODE` into the PostgreSQL DSN and libpq uses standard `PGSSLROOTCERT` when no sslrootcert DSN field is supplied. `local/test-tls-fixture.sh` verifies this with the installed Laravel/PDO/libpq connector against disposable local TLS PostgreSQL: trusted CA succeeds, wrong hostname, official RDS CA against a fixture-signed server, and missing CA all fail. Fixture private keys are generated outside the image and cleaned up; this is not real RDS connectivity validation.

Entry point never migrates, imports, or seeds. PHP `/up` bootstraps Laravel without a DB query; `/readyz` also runs SELECT 1. Nginx `/healthz` is not an application readiness check. App read-only filesystem requires writable emptyDir mounts at storage, bootstrap/cache, /tmp (UID/GID 82). App Pods use 30s preStop deregistration delay and 90s total termination grace; rolling update maxUnavailable=0/maxSurge=1. Web runs as nginx UID101 with dropped caps; root filesystem remains writable because official CRS entrypoint renders configs under /etc.

HTTP ALB is a temporary CIDR-restricted test endpoint, not production TLS. `/apps` and descendants are fixed-response 404; `/app` routes only to Reverb; normal requests traverse WAF+FPM in the same Pod. Dedicated VPC XFF trust uses ALB's rightmost appended client address and ignores caller X-Real-IP. Reverb stays single replica without Redis. NetworkPolicy enforcement requires VPC CNI network policy support enabled; manifests alone do not enable the controller. Policies restrict ingress only; no obsolete PostgreSQL ingress policy or IP-pinned RDS egress policy is shipped. Private RDS TCP5432 access is controlled by its security group admitting the EKS worker/node security group; DNS resolution and managed endpoint IP rotation remain possible. Security groups still enforce the restricted ALB path. Lab avatars use private S3 + IRSA (IMDS disabled). Local integration deliberately uses local ephemeral avatars and does NOT validate multi-replica S3 uploads.

Disposable local stack: WSL `sh infra/eks-lab/local/build-wsl.sh`, then from the Linux build context `sh infra/eks-lab/local/up.sh` and `sh infra/eks-lab/local/smoke.sh`. Context `/root/manaleague-eks-lab-context`; named Compose project `manaleague-eks-lab`; only published port `127.0.0.1:18080`; DB volume belongs only to this project. `down.sh` deletes only this project's disposable containers/volume. Random credentials stay in ignored `local/.env.local`, never stdout. No AWS or Kubernetes remote commands are part of local tests.
